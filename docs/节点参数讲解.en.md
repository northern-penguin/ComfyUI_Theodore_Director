# Theodore Director Node Parameter Reference

This document describes the eight Theodore Director nodes in the current source tree. Inputs are separated into editable widgets, connection-driven inputs, and outputs.

> Important: the final effect of a parameter depends on workflow wiring. The bundled V7 workflow already contains the recommended generation and standalone second-pass connections.

## 1. Theodore Director Project

Node ID: `TheodoreDirector_Project`

### Editable controls

| Parameter | Default | Effect |
|---|---|---|
| `Open Director` | — | Opens the full-screen visual editor. “Save to workflow” writes the edited plan into the hidden `plan_json` widget. |
| `plan_json` / Project Data | Built-in sample | The complete Director Plan JSON. The UI hides this widget for normal use; advanced fields can also be changed by importing edited JSON. |

Every generation- or result-affecting plan change updates `plan_hash`, including Project name, Run ID, media, prompts, durations, enabled states, latent relay switches, second-sampling switches, and continuity settings. The hidden internal Project ID exists only for JSON backward compatibility and is excluded from hashing. Resume accepts old output only when both plan and shot hashes match; the first automatic upgrade from a v1–v3 plan produces a one-time new plan hash.

### Outputs

| Output | Meaning |
|---|---|
| `PLAN` | Immutable plan object consumed by other Theodore nodes. |
| `plan hash` | SHA-256 of the canonical plan, used for consistency and resume checks. |
| `project name` | User-facing project name; currently used in the output directory. |
| `active shots` | Number of enabled shots. Disabled shots are excluded. |

## 2. Theodore Director - Current Shot

Node ID: `TheodoreDirector_SelectShot`

### Inputs

| Parameter | Default | Effect |
|---|---:|---|
| `plan` | Connection required | Plan emitted by the Project node. |
| `queue_index` | `0` | Zero-based Impact index over enabled shots only. Disabled shots do not consume an index. Out-of-range values fail. |
| `base_seed` | `123456790` | If a shot has no explicit seed, the effective seed is `base_seed + active_index`. A shot seed takes priority. |
| `resume_mode` | `fresh` | Controls completed-result inspection as described below. |

### Actual `resume_mode` behavior

| Value | Current behavior |
|---|---|
| `fresh` | Ignores completion records and executes the enabled shot at `queue_index`. It does not reset the index to zero. |
| `resume` | Scans forward from `queue_index`, skips fully completed shots, and selects the first incomplete shot. It stops with an error when all shots are complete. |
| `retry_failed` | Currently identical to `resume`; the system does not yet persist a distinct `failed` status. |
| `overwrite_current` | Currently identical to `fresh`; it does not delete old media, but forces the current index and replaces result metadata after success. |

A shot is complete only when result status, plan hash, and shot hash match and the video, tail frame, and—when required—AV latent all exist and are non-empty.

> Current implementation note: SelectShot always receives a numeric `base_seed`, so it overrides `defaults.baseSeed` stored in the plan even when the port is unconnected and using its widget default. Bundled V6 also connects an external `PrimitiveInt`. The Director Project Base seed is currently stored and hashed but does not directly control the effective generation seed.

### Outputs

`SHOT` carries the selected shot and queue state. Other outputs expose the raw prompt, negative prompt, duration, effective seed, shot ID, active/source indices, active count, first/last flags, next index, `has_next`, shot hash, `latent relay`, and `second sampling`. Both switches are single Booleans for the current shot already selected from the Impact `queue_index`. Relay selects Motion Context versus original H3 conditioning; second sampling selects the second-pass image versus the first-pass image in a dual graph. The first enabled shot always emits false for relay. In a single graph, the second-sampling output remains unconnected. The H3 Adapter compiled prompt is used for generation; the standalone negative-prompt output may not be connected to the model.

## 3. Theodore Director - MiniMax H3 Adapter

Node ID: `TheodoreDirector_H3Adapter`

This node has no editable widgets. `PLAN + SHOT` control all behavior. It:

- compiles `{{ref:alias}}` into `<Picture N>`, `<Video N>`, and `<Audio N>`;
- orders fixed media first, then first prompt references;
- loads only media active for the current shot;
- enforces 9-picture, 3-video, 3-effective-audio, 12-mixed-file, and duration limits;
- converts shot duration to H3's `17n+5` frame grid and compensates later-shot context trimming.

Outputs include the compiled prompt, generated and expected delivery frames, a reference-map JSON string, nine picture ports, three video ports, three paired-video-audio ports, and three standalone-audio ports.

## 4. Theodore Director - Output Paths

Node ID: `TheodoreDirector_OutputPaths`

This node has no editable widgets. It derives stable paths from Project name, Run ID, and shot ID. The Impact active index does not affect shot filenames. Unsafe characters become underscores and each path segment is capped at 80 characters.

```text
ComfyUI/output/TheodoreDirector/<Project name>_<Run ID>/
  <shot-id>_video_*.mp4
  latent_context/clip_00001.safetensors
  tail_frames/<shot-id>_tail_*.png
  shot_results/<shot-id>_result.json
  manifest.json
```

Outputs provide the complete `PATHS` object, video prefix, latent load directory, latent save prefix, tail prefix, manifest path, and current-shot result path.

## 5. Theodore Director - Commit Result

Node ID: `TheodoreDirector_CommitResult`

| Parameter | Type | Effect |
|---|---|---|
| `plan` / `shot` / `paths` | Required connections | Supply expected locations and hashes. |
| `completion_signal` | Required connection | Forces the save chain to finish; the same value is forwarded as `signal`. |
| `tail_path` | Required connection | Path or bare filename returned by the tail saver. It is resolved against `tail_prefix`. |
| `latent_path` | Optional connection | Absolute or relative path returned by the AV latent saver. |
| `latent_required` | `true` | When enabled, a missing or empty latent blocks commit and queue advancement. When disabled, only video and tail are required. |

After validation, the node atomically writes the shot result and project manifest, then emits `next_index` and `has_next`. It does not create or repair media.

## 6. Theodore Director - Postprocess Second Pass Source

Node ID: `TheodoreDirector_PostprocessSecondPassSource`

This hidden request source powers the V7 standalone second-pass branch. It validates the project, run, stable shot ID, and selected output video, then emits an independent `PLAN`, `SHOT`, source frames, original audio, FPS, and seed. Disabled shots may still use historical first-pass results. Users should not edit its request JSON manually.

## 7. Theodore Director - Save Standalone Second Pass

Node ID: `TheodoreDirector_SaveSecondPass`

This is the partial-execution target for standalone refinement. It saves a new `<shot-id>_video_2nd_*` result with provenance metadata and never overwrites the first pass, advances Impact, or changes continuity latent/tail outputs. It remains in NEVER mode until the Director serializes a specific postprocess request.

## 8. Theodore Director - Import Legacy Script

Node ID: `TheodoreDirector_LegacyImport`

| Parameter | Default | Effect |
|---|---|---|
| `script` | One-shot example | Imports legacy text. Segments must be separated by a line containing only `===`; every segment needs `title & duration & prompt`. |
| `project_name` | `Imported Project` | Project name for the imported plan. Blank values fall back to the default. |
| `base_seed` | `123456790` | Default seed stored in the imported plan. |

It emits imported plan JSON and `PLAN`. Imported plans use `legacy_generation_duration`, where the entered duration represents legacy generation duration rather than final post-trim delivery duration.

## Current-version caveats

- `retry_failed` currently equals `resume`; `overwrite_current` currently equals `fresh`.
- The visual editor does not expose per-shot `seed`, `audioDurationSeconds`, or advanced continuity fields. They can be changed by exporting, editing, and importing JSON.
- The media library may exceed one H3 call's capacity, but every enabled shot must pass validation independently.
- Changing the plan changes its hash. Old output under the same Run ID will not be treated as valid completion for the changed plan.
