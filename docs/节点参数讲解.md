# Theodore Director 节点参数讲解

本文对应当前仓库源码，说明 Theodore Director 的 6 个节点。参数分为三类：节点上可直接编辑的控件、应由连线提供的输入，以及仅用于观察或继续接线的输出。

> 重要：节点参数的最终效果取决于工作流接线。成品 Impact V6 工作流已经完成推荐接线，不建议随意断开 `PLAN`、`SHOT`、`PATHS` 或保存完成信号。

## 1. Theodore Director Project

节点类型：`TheodoreDirector_Project`

### 可编辑参数

| 参数 | 默认值 | 效果 |
|---|---|---|
| `打开 Theodore 导播台 / Open Director` | — | 打开全屏可视化编辑器。点击“保存到工作流”后，计划写回隐藏的 `plan_json`。 |
| `plan_json` / Project Data | 内置示例计划 | 完整 Director Plan JSON。前端会隐藏该文本框，日常应通过导播台编辑；也可通过导入 JSON 修改高级字段。 |

任何计划内容变化都会改变 `plan_hash`，包括项目设置、素材、提示词、时长、启用状态和连续性配置。`resume` 只认可 plan hash 与 shot hash 均匹配的旧结果。

### 输出

| 输出 | 含义 |
|---|---|
| `PLAN` | 后续 Theodore 节点使用的不可变计划对象。 |
| `plan hash` | 规范化计划的 SHA-256，用于结果一致性与续跑判断。 |
| `project name` | 用户项目名称。当前用于输出目录名。 |
| `active shots` | 已启用分镜数量，不包含关闭的分镜。 |

## 2. Theodore Director - Current Shot

节点类型：`TheodoreDirector_SelectShot`

### 输入参数

| 参数 | 默认值 | 效果 |
|---|---:|---|
| `plan` | 必须连接 | Project 节点输出的计划。 |
| `queue_index` | `0` | Impact 当前索引，按“启用分镜”计数且从 0 开始。关闭的分镜不占索引。超出范围会报错。 |
| `base_seed` | `123456790` | 没有分镜专用 seed 时，实际 seed 为 `base_seed + active_index`。分镜专用 seed 优先。 |
| `resume_mode` | `fresh` | 决定是否检查已完成结果，详见下表。 |

### `resume_mode` 当前真实行为

| 值 | 当前行为 |
|---|---|
| `fresh` | 忽略完成清单，直接执行 `queue_index` 指向的启用分镜。不会自动把索引重置为 0。 |
| `resume` | 从 `queue_index` 开始向后扫描，跳过完整完成的分镜，选择第一个未完成分镜。全部完成时停止并报错。 |
| `retry_failed` | 当前与 `resume` 相同；系统尚未写入独立的 `failed` 状态。 |
| `overwrite_current` | 当前与 `fresh` 相同；它不会删除旧文件，只会强制执行当前索引并在成功时替换结果清单。 |

“完整完成”要求结果 JSON 的状态、plan hash、shot hash 均匹配，并且视频、尾帧以及需要时的 AV latent 都存在且非空。

> 当前实现提示：SelectShot 的 `base_seed` 始终是数值输入，因此它会覆盖计划中保存的 `defaults.baseSeed`，即使端口未接线也会使用节点默认值。成品 V6 还把外部 `PrimitiveInt` 接到了这里。导播台“项目设置”中的 `Base seed` 当前只会被保存并参与 plan hash，不直接控制实际生成 seed。

### 输出

| 输出 | 含义 |
|---|---|
| `SHOT` | 当前分镜对象及队列状态，供适配器、路径和提交节点使用。 |
| `prompt` / `negative_prompt` | 原始分镜正向/负向提示词。注意：成品 V6 主要使用 H3 Adapter 的编译提示词，负面提示词输出当前未必接入模型。 |
| `duration_seconds` | 用户填写的分镜时长。 |
| `seed` | 分镜专用 seed，或 `base_seed + active_index`。 |
| `shot_id` | 当前分镜稳定 ID。 |
| `active_index` | 当前分镜在启用分镜列表中的 0 起始索引。 |
| `source_index` | 当前分镜在完整分镜列表中的 0 起始索引。 |
| `active_count` | 启用分镜总数。 |
| `is_first` / `is_last` | 是否为启用序列的首段/末段。 |
| `next_index` | 有下一段时为 `active_index + 1`，末段时重置为 `0`。 |
| `has_next` | 是否还有下一段，通常连接 Impact Queue Trigger。 |
| `shot_hash` | 当前分镜、适用素材、全局提示词和连续性设置的 SHA-256。 |

## 3. Theodore Director - MiniMax H3 Adapter

节点类型：`TheodoreDirector_H3Adapter`

该节点没有直接可编辑控件，参数全部来自 `PLAN + SHOT`。它负责：

- 把 `{{ref:alias}}` 编译成 `<Picture N>`、`<Video N>`、`<Audio N>`；
- 按固定素材和提示词首次引用顺序分配槽位；
- 只加载当前分镜实际激活的媒体；
- 校验 H3 的 9 图、3 视频、3 路有效音频、12 个混合文件及 15 秒时长限制；
- 将分镜时长换算到 H3 的 `17n+5` 合法帧数，并补偿后续段上下文裁切。

主要输出：`H3 prompt`、`H3 frames`、`delivery frames`、`reference map`，以及 9 个图片、3 个视频、3 个视频伴音和 3 个独立音频物理端口。视频伴音端口必须与对应视频保持相同物理索引。

## 4. Theodore Director - Output Paths

节点类型：`TheodoreDirector_OutputPaths`

没有直接可编辑控件。它根据项目名称、Run ID、分镜 ID 和启用索引生成稳定路径。名称中的空白和不安全字符会转换为下划线，每段最长 80 个字符。

```text
ComfyUI/output/TheodoreDirector/<Project name>_<Run ID>/
  001_<shot-id>_video_*.mp4
  latent_context/clip_00001.safetensors
  tail_frames/001_<shot-id>_tail_*.png
  001_<shot-id>_result.json
  manifest.json
```

| 输出 | 用途 |
|---|---|
| `PATHS` | 提交节点使用的完整路径对象。 |
| `video_prefix` | SaveVideo 文件名前缀。 |
| `latent load directory` | H3 Motion Context Load Latent 的目录。 |
| `latent_save_prefix` | H3 Motion Context Save Latent 的文件名前缀。 |
| `tail_prefix` | 尾帧保存前缀。 |
| `manifest_path` | 项目总清单相对路径。 |
| `shot_result_path` | 当前分镜结果 JSON 相对路径。 |

## 5. Theodore Director - Commit Result

节点类型：`TheodoreDirector_CommitResult`

### 输入参数

| 参数 | 类型 | 效果 |
|---|---|---|
| `plan` / `shot` / `paths` | 必须连接 | 提供计划哈希、分镜哈希和预期保存位置。 |
| `completion_signal` | 必须连接 | 确保保存链已经执行；原值会作为 `signal` 输出。 |
| `tail_path` | 必须连接 | 尾帧保存节点返回的路径或纯文件名。提交节点会按 `tail_prefix` 的真实目录解析。 |
| `latent_path` | 可选连线 | AV latent 保存节点返回的绝对或相对路径。 |
| `latent_required` | `true` | 为真时，latent 缺失或空文件会阻止提交和下一段；为假时只要求视频与尾帧。 |

提交成功后会原子写入分镜结果 JSON 与项目 manifest，再输出 `next_index` 和 `has_next`。它不会生成媒体，也不会修复损坏文件；任一必需文件不存在时会报错并阻止 Impact 前进。

## 6. Theodore Director - Import Legacy Script

节点类型：`TheodoreDirector_LegacyImport`

| 参数 | 默认值 | 效果 |
|---|---|---|
| `script` | 示例单段脚本 | 导入旧版整段文本。分段必须用独占一行的 `===` 分隔，每段必须包含 `标题 & 时长 & 提示词`。 |
| `project_name` | `Imported Project` | 写入导入计划的项目名称。空值回退到默认名称。 |
| `base_seed` | `123456790` | 写入导入计划的默认 seed。 |

输出 `imported plan JSON` 与 `PLAN`。导入计划自动使用 `legacy_generation_duration`：填写的时长表示旧版“生成时长”，而不是裁切后的最终交付时长。

## 当前版本注意事项

- `retry_failed` 尚未区别于 `resume`；`overwrite_current` 尚未区别于 `fresh`。
- 导播台 UI 当前不显示分镜专用 `seed`、`audioDurationSeconds` 和连续性高级字段；它们可通过导出、编辑并重新导入 JSON 设置。
- 素材库可超过 H3 单次容量，但每个启用分镜必须单独通过预检。
- 修改计划后 hash 会变化；使用原 Run ID 时，旧结果不会被 `resume` 判定为当前计划的有效完成结果。
