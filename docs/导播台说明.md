# Theodore 导播台使用说明

## 1. 打开、保存与关闭

在 `Theodore Director Project` 节点点击“打开 Theodore 导播台”。同一时间只允许打开一个导播台窗口。

- **保存到工作流**：先执行完整预检，再把计划写入 Project 节点的隐藏 JSON，并关闭窗口。之后还需要在 ComfyUI 中保存工作流文件，才能永久写入磁盘。
- **关闭**或 `Esc`：关闭窗口，不把本次窗口中的未保存修改写回节点。
- **导出**：把窗口当前状态下载为 `<Project name>.director.json`；即使尚未保存到工作流，也会导出当前编辑状态。
- **导入**：只把 JSON 载入当前窗口。必须再点“保存到工作流”才会写回节点。
- **EN / 中文**：切换界面语言；部分字段标签目前固定为双语或中文。

## 2. 推荐设置顺序

1. 在“项目设置”填写 Project name 和 Run ID。
2. 在“素材库”上传或填写所有候选参考素材，并设置稳定别名。
3. 在“分镜”中建立顺序、时长和提示词，使用别名引用素材。
4. 查看右侧 H3 编译预览，逐段清除错误。
5. 保存到工作流，确认 Impact 当前索引和 `resume_mode`，再 Queue。

## 3. 项目设置

| 字段 | 作用与建议 |
|---|---|
| `Project name` | 人类可读项目名，也是素材与输出目录的主要部分。上传素材保存到 `ComfyUI/input/theodore_director/<Project name>/`，不安全字符会转为下划线；改变它也会改变输出路径。 |
| `Run ID` | 区分同一项目的不同运行。输出目录为 `<Project name>_<Run ID>`。新一轮生产建议换 Run ID，避免与旧文件混放。 |
| `FPS` | 时长换算与预计交付帧数使用的帧率，必须大于 0。H3 参考视频仍会在加载时统一到 24 fps。 |
| `Base seed` | 保存到计划并参与 plan hash。当前 SelectShot 总会使用自身的数值 `base_seed` 输入覆盖它；成品 V6 又外接了独立整数节点，因此该界面字段目前不直接控制实际生成 seed。 |
| `提示词前缀` | 自动添加在每个分镜提示词之前，也参与别名解析和 hash。 |
| `提示词后缀` | 自动添加在每个分镜提示词之后，也参与别名解析和 hash。 |

高级连续性字段目前不在可视化设置页显示，可以通过导出 JSON 修改后导入：

> 协议 v4 仍在 JSON 内保留 `project.id`，但它只是隐藏的向后兼容元数据，不在界面显示，也不参与 plan hash。新计划会自动生成该值，旧 v1–v3 计划会自动升级。

- `continuity.mode`：当前成品工作流使用 `h3_av_latent`。
- `videoContextFrames`：H3 允许 `5`、`22`、`39`、`56`，用于后续段视频上下文和时长补偿。
- `audioContextFrames`：传递给连续性计划；当前时长计算主要使用视频上下文帧数。
- `durationMode`：`final_output` 表示输入最终成片时长；`legacy_generation_duration` 保留旧脚本行为。

## 4. 素材库

### 添加和上传

点击 `+ image`、`+ video` 或 `+ audio` 创建素材。可以填写 ComfyUI input 相对路径，也可以用文件选择器上传。

选择文件后，文件按钮右侧会显示上传状态；上传完成后显示实际保存的文件名。素材卡片会直接显示图片缩略图、视频播放器或音频播放器。预览通过 ComfyUI 的 `input` 读取接口完成，不会额外复制文件；获准使用的外部绝对路径可以参与执行，但出于浏览器读取安全限制不会显示预览。

素材库工具栏中的“批量导入素材”支持一次选择或拖入图片、视频和音频。文件会先进入确认列表，不会立即写盘：列表中可修改别名、素材类型、时长和视频伴音开关，也可移除单项或清空列表。别名默认由文件名生成，会去掉扩展名与开头的排序编号，把空格和连字符转换为下划线；与现有素材或本批次其他素材重名时自动追加 `_2`、`_3`。非法、重复或与扩展名不匹配的项目会标红并阻止导入。

点击“开始导入”后最多同时上传两个文件，避免大量视频争抢浏览器连接和磁盘带宽。成功项立即加入素材库并默认启用，但不会自动设为固定引用、限定分镜或写入提示词；视频伴音也默认关闭。失败项保留在列表中，可以修正后点击“重试失败项”。批量面板会尝试从视频和音频容器读取时长元数据，读取失败时仍可手动填写；该过程不会解码整段媒体，临时浏览器 URL 会在读取后释放。

上传限制：

- 单个文件最大 2 GiB；
- 图片：PNG、JPG/JPEG、WEBP、BMP；
- 视频：MP4、WEBM、MOV、MKV；
- 音频：WAV、MP3、FLAC、OGG、M4A、AAC；
- 同名文件不会覆盖，服务端会自动增加随机后缀；
- 默认禁止读取任意绝对路径。可信单用户环境可设置 `THEODORE_DIRECTOR_ALLOW_EXTERNAL_PATHS=1` 后重启 ComfyUI。

### 素材字段

| 字段 | 作用 |
|---|---|
| `Alias` | 提示词引用名。项目内不区分大小写唯一；不能留空、包含空白或花括号，也不能以 `.audio` 结尾。建议使用稳定的英文、数字和下划线。 |
| `Kind` | `image`、`video` 或 `audio`。改变类型后要确认文件扩展名和时长仍正确。 |
| `Path` | ComfyUI input 相对路径或获准的绝对路径。启用素材必须有文件。 |
| `Duration` | 视频/音频时长元数据。单素材编辑需手动填写，批量导入会尝试自动读取且允许修改。H3 要求每个视频和每路有效音频为 2–15 秒，并限制总时长 15 秒。 |
| `Fixed order` | 固定素材的排序值；相同值再按别名排序。 |
| `限定分镜 ID` | 逗号分隔。空值表示可用于所有分镜；填写后只进入这些 ID 对应分镜的候选目录。 |
| `启用` | 全局关闭后，所有分镜都无法引用该素材。 |
| `固定引用` | 无需在提示词中出现也会激活并占用 H3 槽位。适合每段都需要的角色/风格锚点。 |
| `启用视频伴音` | 只对视频显示。视频本体用 `{{ref:alias}}`；伴音用 `{{ref:alias.audio}}`。启用后即计入有效音频上限。 |
| `删除` | 从素材库移除。若提示词仍引用该别名，预检会报错。 |

视频伴音可在高级 JSON 中设置独立的 `audioDurationSeconds`；界面没有该字段时会使用视频的 `Duration` 作为伴音时长。

## 5. 分镜编辑

左侧卡片按实际故事顺序排列。`↑`、`↓` 会改变启用序列、seed 偏移、首尾判断和 latent 连续关系，但不会改变基于稳定 `shot ID` 的输出文件名前缀。

| 字段 | 作用 |
|---|---|
| `ID` | 稳定且唯一的机器 ID，同时用于素材范围、hash 和输出文件名。改 ID 后应同步检查素材的“限定分镜 ID”。 |
| `Title` | 显示名称，用于列表和错误提示。 |
| `Duration` | 目标时长，必须大于 0。默认 `final_output` 模式下表示裁切后的最终成片时长。实际帧数会吸附到 H3 的 `17n+5` 网格。 |
| `Enabled` | 关闭后不进入 Impact 活动索引，也不生成。至少要保留一个启用分镜。 |
| `latent接力 / Relay` | 控制当前镜头是否读取上一个启用镜头的 AV latent。开启时走 Motion Context 并裁掉重叠上下文；关闭时作为独立镜头生成且裁切 0 帧。首个启用镜头执行时自动忽略该开关。 |
| `高清处理` | 逐镜头选择关闭、超分二采、Latent 放大二采或只超分。模式写入计划并影响 hash；未选中的重分支由 Impact 惰性跳过。 |
| `提示词` | 当前分镜正文。使用 `{{ref:alias}}` 引用图片、视频或独立音频，使用 `{{ref:video_alias.audio}}` 引用视频伴音；也可以输入 `@` 从当前可用素材中快速选择。 |
| `负面提示词` | 存入计划并由 SelectShot 输出；当前成品 H3 V6 工作流未必把该输出接入模型，请检查工作流接线。 |
| `本镜头素材` | 取消勾选会把素材 ID 写入本镜头禁用列表。它优先于素材的全局启用、固定引用和限定分镜范围。 |

“本镜头素材”以卡片显示：图片和视频提供缩略预览，视频、音频提供浏览器播放控件。取消勾选后卡片会变淡，表示该素材不会进入当前分镜；这不会改变素材库中的全局启用状态。左键点击卡片底部的文件名会把该素材别名复制为 `{{ref:别名}}`，可直接粘贴到提示词中。

在分镜提示词中输入 `@` 会在光标附近打开“参考素材”菜单，只列出全局启用、路径非空、适用于当前镜头且没有被本镜头禁用的素材。继续输入可以按别名或原文件名筛选；方向键切换候选，`Enter` 或 `Tab` 选择，`Esc` 关闭。选择后，当前 `@查询词` 会被完整替换成 `{{ref:别名}}`，光标停在引用末尾。图片候选使用懒加载缩略图；视频和音频只显示类型图标，不会在菜单内创建播放器或提前解码媒体。该快捷菜单只用于分镜正文，不应用于负面提示词和全局前后缀。

“添加分镜”会创建 5 秒、启用、空提示词的新分镜。分镜卡最左侧的 `×` 用于删除；删除当前分镜后自动选中相邻分镜，最后一个分镜不能删除。

左侧镜头栏底部的“批量处理镜头”会打开独立面板。列表可集中修改每个镜头的名称、启用状态、具体时长和 `latent 接力` 开关；顶部的“全部启用/全部禁用”可一次切换所有镜头，并显示当前启用数量。修改先保存在面板临时副本中，点击“应用更改”后才写入当前导播台，点击“取消”则放弃。面板还支持两种快捷操作：输入一个秒数后一键覆盖所有镜头时长；输入新增数量与每个镜头的秒数后一次创建多个镜头。每次最多新增 100 个镜头，新镜头默认启用、开启 latent 接力并选择“超分二采”，同时自动生成不重复的 `shot_XXX` ID。

左侧列表上方提供“批量处理模式”下拉框。选择四种模式之一并点击“应用到全部镜头”，会把该模式一次写入全部镜头；之后仍可逐镜头调整。

四种主流程模式的执行语义：

- **关闭二采**：直接使用一采解码画面。
- **超分二采**：一采画面经 RTX 1.5× ULTRA 超分、VAE 重编码后进入第二次 H3 采样。
- **Latent 放大二采**：使用 V7.1 方案 C，将第一采 denoised 视频 latent 经学习型 3D 网络放大 1.5×，同步放大 conditioning，并对视频/音频 latent 分别正确重加噪后执行二采。
- **只超分**：使用 RTX 1.5× 画面，不执行 VAE 重编码和第二次采样。

所有模式继续使用第一采音频，并保存第一采 AV latent 供后续镜头接力。关闭和只超分不会加载二采 LoRA；Latent 模式不会执行 RTX 节点。

分镜专用 `seed` 已受计划协议支持，但当前界面没有输入框。可在导出的分镜对象中设置 `"seed": 123`，再导入保存；`null` 表示使用 `base_seed + active_index`。

## 6. 别名编译和排序

可用于当前分镜的素材必须同时满足：全局启用、分镜范围匹配、未被本镜头禁用。

激活顺序：

1. 所有“固定引用”素材，按 `Fixed order`、别名排序；
2. 提示词前缀、正文、后缀中第一次出现的别名；
3. 同一素材重复出现不会重复占槽。

随后按类型独立编号：图片为 `<Picture N>`，视频为 `<Video N>`；启用的视频伴音先占 `<Audio N>`，独立音频随后编号。素材库总量可以很大，但每个分镜最多 9 图、3 视频、3 路有效音频、12 个混合文件。

示例：

```text
{{ref:hero}} 穿过 {{ref:street}}，动作参考 {{ref:walk_cycle}}，
环境声参考 {{ref:walk_cycle.audio}}。
```

建议始终写别名，不直接手写 `<Picture 1>`。直接编号只有在本轮实际槽位存在时才合法，而且素材顺序变化后容易指错。

分镜正文、全局提示词前缀和后缀会实时高亮完整的 `{{ref:...}}` 引用。绿色表示引用在当前上下文可用；红色表示别名不存在、素材被禁用、路径为空、不适用于当前镜头，或 `.audio` 没有对应的已启用视频伴音。全局前后缀只有在所有启用分镜中都可用时才显示绿色。不完整的引用语法保持普通文字。高亮只检查计划数据，不实时确认磁盘文件是否仍然存在；最终结果以后端 H3 Adapter 校验为准。

## 7. H3 编译预览

右侧的“H3 编译预览”和“生成结果”是两个可独立展开、收起的菜单。H3 预览只针对当前分镜，实时显示：

- Picture、Video、Audio 和混合文件计数；
- 容量、时长、缺失素材和无效伴音错误；
- `<Picture N>` / `<Video N>` / `<Audio N>` 到别名的映射；
- 合并前缀、正文、后缀后的最终编译提示词。

浏览器预检用于即时反馈，Python 后端仍是执行时的最终权威。点击“保存到工作流”会对所有启用分镜执行预检，而不只检查当前页面。

“生成结果”会根据 Project name、Run ID、当前分镜在启用序列中的序号和分镜 ID，查询与 Output Paths 节点相同的预期视频前缀。找不到时显示空状态；找到时按生成时间从新到旧列出这个镜头的全部历史结果，并默认播放最新结果。点击任意结果会复用同一个主播放器切换视频，不会同时创建大量播放器。列表缩略图只在接近可视区域时加载并停在视频前段画面，滚出预加载区域后会卸载对应媒体资源，因此大量历史结果不会一次性加载。导播台不会持续轮询磁盘，生成完成后可点击“刷新结果”。修改项目名、Run ID、分镜 ID 或启用顺序后，查询位置也会随之改变。新增查询接口需要重启 ComfyUI 后才能生效。

## 8. 后处理与合并视频

进入“后处理”后可在“合并视频”和“单独二采”两个页签之间切换，默认仍显示合并视频。

### 单独二采

“单独二采”会列出全部镜头及其历史生成结果，并继续使用惰性缩略图和单播放器预览。顶部可选择“超分二采”“Latent 放大二采”或“只超分”；点击允许处理的结果时，导播台向 ComfyUI 提交只执行所选后处理支流的局部任务，最后保留原音轨另存为新结果。Latent 模式会从保存的视频重建 AV latent 后执行方案 C，不会读取跨段 continuity latent。

- 不重跑一采，不启动 Impact，不读取或更新 latent 接力。
- 已禁用镜头仍可处理历史一采结果。
- 一采和处理结果并存；后处理分别使用 `_2nd_sr`、`_2nd_latent`、`_upscaled` 文件名前缀。
- 一采和没有阶段元数据的旧结果可执行三种处理；超分二采和 Latent 二采结果只能继续执行“只超分”；只超分结果不能再次处理。前端会根据当前所选模式显示具体禁用原因，后端也执行相同校验。
- 推荐“一采 → Latent 放大二采 → RTX 只超分”。“超分二采 → 只超分”虽然允许，但会重复 RTX 1.5× 放大，通常没有必要；任何二采结果都不能再次进入扩散二采，因此不会被伪装成普通二采来执行三采。
- 二采使用点击时导播台中的当前提示词、素材引用和 seed。
- 任务完成后列表自动刷新；关闭导播台不会取消已经进入 ComfyUI 队列的任务。

该功能要求当前工作流包含新版 V7 的独立二采支流，并要求 ComfyUI 支持 `partial_execution_targets`。若缺少支流或局部执行能力，导播台会停止提交，绝不会退化为运行整个 Impact 工作流。

“后处理”与分镜、素材库、项目设置并列。进入后处理后，导播台会展示计划中的所有镜头；启用镜头默认全部勾选，禁用镜头保留在列表中但不能参加当前合并。点击“一键全选/全部取消”可以批量切换所有启用镜头。也可以在范围框中输入起始镜头 `m` 和结束镜头 `n`，点击“确认范围”后仅选中当前分镜顺序中第 `m` 至第 `n` 个镜头（包含两端）；落在范围内的禁用镜头仍不会被选中。

点击“打开结果文件夹”会在系统文件管理器中打开当前 `Project name + Run ID` 对应的 `output/TheodoreDirector/<Project name>_<Run ID>/` 目录。目录尚不存在时会自动创建。前端不会传递任意磁盘路径，后端始终从当前项目字段重新计算并约束在 ComfyUI `output` 目录内。新增该接口后需要重启 ComfyUI 才能使用。

每张镜头卡片显示镜头 ID、名称、计划时长和该镜头的全部生成结果。结果默认选择最新一项，一个镜头只能选择一个结果；点击结果可改变合并版本，点击右侧播放按钮会在共享播放器中预览。卡片缩略图沿用生成结果的惰性加载机制，只有接近可视区域的结果才加载媒体，滚远后会卸载，因此大量镜头与历史版本不会一次性建立播放器。

点击“合并所选视频”后，后端会再次验证每个文件确实属于对应镜头和当前 Project name / Run ID，然后按照当前分镜顺序调用 FFmpeg concat 进行无损流复制。合并不提交 ComfyUI 工作流、不占用生成队列或 GPU，也不会重新编码。不同片段的编码、分辨率、帧率、像素格式或音频参数不兼容时，FFmpeg 会拒绝合并并在界面显示错误，不会自动降低画质转码。

合并结果直接保存为运行目录中的 `merged_video_00001_.mp4`、`merged_video_00002_.mp4` 等，不覆盖历史文件。页面下方会列出全部合并结果，并复用单播放器与惰性缩略图进行预览。该功能需要 FFmpeg；程序依次查找 `THEODORE_DIRECTOR_FFMPEG`、系统 `PATH` 和可选的 `imageio-ffmpeg`。新增后端接口后必须重启 ComfyUI。

## 9. 保存、执行与续跑

推荐普通生产选择 `resume`。它从 Impact 当前索引向后跳过完整完成的分镜。完整结果必须同时通过状态、plan hash、shot hash、视频、尾帧和必要 latent 校验。

当前模式差异：

- `fresh`：强制执行当前索引；不会自动回到第 1 段。
- `resume`：跳过完整结果。
- `retry_failed`：当前与 `resume` 相同。
- `overwrite_current`：当前与 `fresh` 相同。

输出目录：

```text
output/TheodoreDirector/<Project name>_<Run ID>/
├─ <shot-id>_video_*.mp4
├─ latent_context/clip_00001.safetensors
├─ tail_frames/<shot-id>_tail_*.png
├─ shot_results/<shot-id>_result.json
└─ manifest.json
```

视频、尾帧和结果 JSON 使用稳定的 `shot ID` 作为文件名前缀；禁用、重新启用或移动其他镜头不会再改变该镜头的查询前缀。导播台同时识别旧版的 `<执行序号>_<shot-id>_*` 历史文件，被禁用的镜头仍可查看历史结果，但不会参加当前执行或视频合并。修改提示词、素材、时长、latent 接力、高清处理模式或连续性设置会改变 hash；旧结果仍保留在磁盘，但 `resume` 不再把它视为当前计划的有效完成结果。升级前位于运行目录根层的旧结果 JSON 仍可用于续跑，新结果统一写入 `shot_results/`。无论当前镜头采用何种处理模式，它的第一采 AV latent 都会照常保存、写入结果并参与完整性校验，以便之后改为接力或继续向后生成。希望保留多套输出时，应修改 Run ID。

## 10. 常见问题

- **保存按钮拒绝保存**：按弹窗列出的分镜逐项修复别名、文件、时长或容量错误。
- **上传后找不到文件**：确认 Project name 与上传时一致、文件仍在对应 input 子目录，并已重启受环境变量影响的服务。旧版按 Project ID 上传的素材不会被自动移动，可保留原路径或重新选择文件上传。
- **提示词仍出现 `{{ref:...}}`**：别名不存在、素材被禁用，或没有经过 H3 Adapter 输出。
- **伴音报错**：确认素材类型是 video、已勾选视频伴音、文件确有音轨且时长元数据为 2–15 秒。
- **修改 Base seed 没有效果**：这是当前实现限制；SelectShot 的数值 `base_seed` 输入优先，成品 V6 还默认连接了外部整数节点。
- **旧输出没有被跳过**：检查 Run ID、路径结构、plan/shot hash 和 result JSON；仅有尾帧不足以通过当前 resume 校验。
- **合并按钮不可用**：至少选择一个镜头，并确保每个已选镜头都选择了一个生成结果。
- **提示找不到 FFmpeg**：将 FFmpeg 加入系统 `PATH`，或把 `THEODORE_DIRECTOR_FFMPEG` 设置为 ffmpeg 可执行文件的完整路径，然后重启 ComfyUI。
- **FFmpeg 报参数不兼容**：当前只做无损流复制；请确保所选片段具有相同的视频、音频和容器参数，或先在外部统一编码。
