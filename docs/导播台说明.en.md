# Theodore Director UI Guide

## 1. Opening, saving, and closing

Click “Open Theodore Director” on the `Theodore Director Project` node. Only one editor window can exist at a time.

- **Save to workflow** validates the plan, writes it to the hidden Project JSON, and closes the editor. Save the ComfyUI workflow afterward to persist it to disk.
- **Close** or `Esc` discards changes that have not been saved back to the node.
- **Export** downloads the editor's current state as `<Project name>.director.json`, including edits not yet saved to the workflow.
- **Import** loads JSON into the current editor session. Click “Save to workflow” afterward to apply it to the node.
- **EN / 中文** switches the UI language. Some field labels are currently bilingual or fixed Chinese text.

## 2. Recommended setup order

1. Set Project name and Run ID.
2. Upload or enter all candidate media and assign stable aliases.
3. Build the shot order, durations, and prompts using alias references.
4. Review the H3 compile preview for every shot.
5. Save to the workflow, verify the Impact index and `resume_mode`, then queue.

## 3. Project settings

| Field | Effect and recommendation |
|---|---|
| `Project name` | Human-readable name and the main component of both media and output directories. Uploads go to `ComfyUI/input/theodore_director/<Project name>/`; unsafe characters become underscores. Changing it also changes output paths. |
| `Run ID` | Separates runs of the same project. Output uses `<Project name>_<Run ID>`. Use a new Run ID for a new production run. |
| `FPS` | Used for duration and expected-frame calculations and must be positive. H3 reference video is still resampled to 24 fps during loading. |
| `Base seed` | Stored in the plan and included in plan hashing. SelectShot currently always overrides it with its numeric `base_seed` input; bundled V6 also connects a separate integer, so this UI field does not directly control generation seed. |
| `Prompt prefix` | Prepended to every shot; participates in reference resolution and hashing. |
| `Prompt suffix` | Appended to every shot; participates in reference resolution and hashing. |

Advanced continuity fields are not exposed in the visual settings page. They can be edited in exported JSON and imported again:

> Protocol v4 still retains `project.id` in JSON, but only as hidden backward-compatibility metadata. It is not shown in the UI and is excluded from plan hashing. New plans generate it automatically, and legacy v1–v3 plans are upgraded automatically.

- `continuity.mode`: bundled workflows use `h3_av_latent`.
- `videoContextFrames`: H3 accepts `5`, `22`, `39`, or `56`; used for later-shot context and duration compensation.
- `audioContextFrames`: stored in the continuity plan; frame calculation currently primarily uses video context frames.
- `durationMode`: `final_output` treats duration as post-trim delivery duration; `legacy_generation_duration` preserves legacy behavior.

## 4. Media library

Use `+ image`, `+ video`, or `+ audio`. Enter a ComfyUI input-relative path or upload a file.

After choosing a file, the area beside the button shows its upload status and then the actual stored filename. Each asset card displays an image thumbnail, video player, or audio player. Previews use ComfyUI's `input` viewing endpoint and do not make another copy. An explicitly allowed external absolute path can still be used during execution, but is not previewed because the browser cannot safely read it.

Upload limits:

- 2 GiB per file;
- images: PNG, JPG/JPEG, WEBP, BMP;
- videos: MP4, WEBM, MOV, MKV;
- audio: WAV, MP3, FLAC, OGG, M4A, AAC;
- existing files are not overwritten; a random suffix is added;
- arbitrary absolute paths are disabled by default. In a trusted single-user environment, set `THEODORE_DIRECTOR_ALLOW_EXTERNAL_PATHS=1` and restart ComfyUI.

`Batch import assets` in the media toolbar accepts mixed images, videos, and audio through multi-selection or drag and drop. Files are staged before anything is written. The review list lets you edit aliases, kinds, durations, and paired video-audio switches, or remove individual items. Aliases are derived from filenames by removing extensions and leading ordinals and converting spaces/hyphens to underscores. Case-insensitive collisions with the library or the current batch receive `_2`, `_3`, and so on. Invalid, duplicate, or extension-mismatched rows are highlighted and block import.

`Start import` uploads at most two files concurrently to avoid saturating browser connections and disk writes. Successful items are added to the library immediately and enabled, but they are not made fixed references, scoped to shots, or inserted into prompts; paired video audio is off by default. Failed rows remain available for correction and retry. The batch panel attempts to read video/audio container duration without decoding the full stream and releases temporary browser URLs afterward; duration remains manually editable when probing fails.

### Media fields

| Field | Effect |
|---|---|
| `Alias` | Prompt reference name. It must be case-insensitively unique, contain no whitespace or braces, and not end in `.audio`. Stable ASCII aliases are recommended. |
| `Kind` | `image`, `video`, or `audio`. Recheck the file and duration after changing it. |
| `Path` | ComfyUI input-relative path or an explicitly allowed absolute path. Enabled media must have a file. |
| `Duration` | Video/audio duration metadata. Single-item editing is manual; batch import attempts to probe it and still allows edits. H3 requires each video/effective audio stream to be 2–15 seconds and limits each category's total to 15 seconds. |
| `Fixed order` | Sort key for fixed media; aliases break ties. |
| `Shot IDs` | Comma-separated scope. Empty means all shots; otherwise the asset is eligible only for matching shot IDs. |
| `Enabled` | Globally disables the asset when cleared. |
| `Fixed reference` | Activates and consumes a slot even when the prompt does not mention the alias. |
| `Include video audio` | Video only. `{{ref:alias}}` means the video; `{{ref:alias.audio}}` means its audio track. Enabling it consumes an effective-audio slot. |
| `Delete` | Removes the asset. Remaining prompt references to its alias will fail validation. |

`audioDurationSeconds` can be set in advanced JSON. When absent, video `Duration` is also used as paired-audio duration.

## 5. Shot editing

Cards on the left define story order. Moving a shot changes active ordering, seed offsets, first/last flags, and latent continuity. Output filenames remain tied to the stable shot ID.

| Field | Effect |
|---|---|
| `ID` | Stable unique machine ID used by media scopes, hashes, and filenames. Update matching Shot IDs on media after changing it. |
| `Title` | Display name used in the list and validation messages. |
| `Duration` | Positive target duration. In `final_output` mode it means final post-trim duration; actual frames snap to H3's `17n+5` grid. |
| `Enabled` | Disabled shots do not consume an Impact active index. At least one shot must remain enabled. |
| `Latent relay` | Controls whether the current shot reads the previous enabled shot's AV latent. Enabled selects Motion Context and trims the overlapping context; disabled generates an independent shot and trims zero frames. The first enabled shot always ignores the switch at execution because no previous latent exists. |
| `Second sampling` | Always visible and stored in the plan. In a dual-sampling workflow, enabling it performs RTX 1.5× upscaling, re-encoding, and the second H3 sample; disabling it lazily skips the complete second-pass chain. A single-sampling workflow has no corresponding execution branch, so this field does not change its result. |
| `Prompt` | Shot body. Use `{{ref:alias}}` for image, video, or standalone audio and `{{ref:video_alias.audio}}` for paired video audio. |
| `Negative prompt` | Stored and emitted by SelectShot. The bundled H3 V6 workflow may not connect it to the model. |
| `Shot media` | Clearing an item adds its asset ID to this shot's disabled list, overriding global enablement, fixed status, and shot scope. |

Shot media is displayed as cards. Images and videos have visual thumbnails, while video and audio cards include browser playback controls. A cleared card becomes dim to show that it will not be supplied to the current shot; the asset's global enabled state is unchanged. Left-click a filename at the bottom of a card to copy its alias as `{{ref:alias}}`, ready to paste into a prompt.

“Add shot” creates an enabled five-second shot with an empty prompt. Use the `×` at the far left of a shot card to delete it. Deleting the selected shot selects an adjacent shot automatically; the final remaining shot cannot be deleted.

`Batch edit shots` at the bottom of the left sidebar opens a separate panel. Its list edits every shot's name, enabled state, exact duration, and `Latent relay` switch in one place. The Enable all / Disable all button switches every shot at once and shows the current enabled count. Changes remain in a temporary copy until `Apply changes` is clicked; `Cancel` discards them. Two shortcuts are available: enter one duration and apply it to every shot, or enter a count plus duration to create several shots at once. Up to 100 shots can be added per action. New shots are enabled by default, enable latent relay and second sampling, and receive unique `shot_XXX` IDs automatically.

Dual-sampling workflows also show a `Second sampling for all: ON/OFF` button above the shot list. Clicking it turns every shot off when all are currently on; from an all-off or mixed state it turns every shot on, including disabled shots.

Per-shot `seed` is supported by the plan protocol but not exposed in the UI. Set `"seed": 123` in exported JSON and re-import it; `null` means `base_seed + active_index`.

## 6. Alias compilation and ordering

An asset is eligible only when globally enabled, in scope for the shot, and not disabled by that shot.

Activation order:

1. fixed assets sorted by Fixed order and alias;
2. first alias occurrences across prompt prefix, body, and suffix;
3. repeated references do not consume extra slots.

Media types are numbered independently. Pictures become `<Picture N>`, videos `<Video N>`, paired video audio takes the first `<Audio N>` positions, and standalone audio follows. The library may be large, but each shot is limited to 9 pictures, 3 videos, 3 effective audio streams, and 12 mixed files.

```text
{{ref:hero}} crosses {{ref:street}}, motion follows {{ref:walk_cycle}},
and ambience follows {{ref:walk_cycle.audio}}.
```

Prefer aliases over hand-written `<Picture 1>` labels. Raw labels are valid only when that slot exists and can silently point at the wrong asset after ordering changes.

The shot body and global prompt prefix/suffix highlight complete `{{ref:...}}` references in real time. Green means the reference is available in the current context. Red means the alias is missing, disabled, has an empty path, is outside the shot scope, or uses `.audio` without an enabled paired video track. A global prefix or suffix is green only when the reference works in every enabled shot. Incomplete syntax remains ordinary text. Highlighting checks plan data only and does not query whether a non-empty path still exists on disk; the backend H3 Adapter remains authoritative at execution time.

## 7. H3 compile preview

The right panel contains two independently collapsible menus: H3 compile preview and Generated result. H3 preview covers only the current shot:

- Picture, Video, Audio, and mixed-file counts;
- capacity, duration, missing-media, and invalid paired-audio errors;
- label-to-alias mapping;
- final prompt after prefix/body/suffix compilation.

Browser validation provides immediate feedback; Python is authoritative at execution time. “Save to workflow” validates every enabled shot, not only the currently visible one.

Generated result derives the same expected video prefix as the Output Paths node from Project name, Run ID, the shot's position in the enabled sequence, and Shot ID. It shows an empty state when no matching file exists. Otherwise it lists every historical result for the shot from newest to oldest and plays the newest one by default. Selecting a result reuses one main player instead of creating many players at once. List thumbnails load only near the visible area and seek to an early video frame; their media resources are unloaded after they leave the preload range, so a large history is never loaded all at once. The editor does not continuously poll the disk; click Refresh after generation finishes. Changing the project name, Run ID, Shot ID, or enabled order also changes the queried path. Restart ComfyUI once to activate the new query endpoint.

## 8. Post-processing and video merging

The Post-process tab now contains two modes: **Merge videos** and **Standalone second pass**. Merge remains the default.

### Standalone second pass

This view lists every shot and all historical results with lazy thumbnails and a single preview player. Choosing **Run second pass** submits a partial ComfyUI job that reads the saved first-pass movie, runs RTX upscaling and the V7 second-pass model chain, keeps the original audio track, and saves a separate refined result.

- It does not rerun the first pass, start Impact, or read/update continuity latent.
- Historical results of disabled shots remain eligible.
- First- and second-pass files coexist; new refinements use `<shot-id>_video_2nd_*`.
- Known second-pass results cannot be refined again. Legacy results without metadata are accepted once.
- The current Director prompt, references, and seed are used when the button is clicked.
- Results refresh automatically after completion; closing the Director does not cancel queued ComfyUI jobs.

The workflow must contain the new V7 standalone branch and ComfyUI must support `partial_execution_targets`. If either capability is missing, the Director blocks submission instead of falling back to the full Impact workflow.

Post-process is a top-level tab beside Shots, Media, and Project. It displays every shot in the plan. All enabled shots are selected by default; disabled shots remain visible but cannot participate in the current merge. Select all / Clear all toggles all enabled shots at once. You can also enter a start shot `m` and end shot `n`, then click Apply range to select only positions `m` through `n` (inclusive) in the current storyboard order. Disabled shots inside the range remain unselected.

Click **Open results folder** to open the current `Project name + Run ID` directory at `output/TheodoreDirector/<Project name>_<Run ID>/` in the system file manager. The directory is created if it does not exist yet. The browser never supplies an arbitrary filesystem path: the backend recomputes the directory from the current project fields and constrains it to ComfyUI's `output` root. Restart ComfyUI after upgrading so the new endpoint is registered.

Each card shows its Shot ID, title, planned duration, and every generated result for that shot. The newest result is selected by default, and exactly one result can be selected per shot. Click a result to choose that version, or use its play button to open the shared preview player. Thumbnails reuse the generated-result lazy loader: media is created only near the visible area and unloaded after scrolling away, avoiding simultaneous players for large projects and histories.

Merge selected videos queues only the hidden `TheodoreDirector_MergeVideos` output node. Local files are revalidated against their shot and current Project name / Run ID. RunningHub results must be trusted-CDN HTTPS URLs and are downloaded with size and redirect limits. The node invokes FFmpeg concat in storyboard order with lossless stream copy. This partial job enters the ComfyUI queue but does not run H3, use the GPU, or re-encode media. FFmpeg rejects incompatible codecs, dimensions, frame rates, pixel formats, or audio parameters and the UI displays the error.

Merged files are stored directly in the run directory as `merged_video_00001_.mp4`, `merged_video_00002_.mp4`, and so on without overwriting history. The lower result panel lists every merge and reuses a single player plus lazy thumbnails. FFmpeg is required: Theodore Director checks `THEODORE_DIRECTOR_FFMPEG`, system `PATH`, then optional `imageio-ffmpeg`. Restart ComfyUI to register the new backend routes.

### RunningHub mode

On a RunningHub hostname the Director selects the RunningHub adapter automatically; Project settings can override it. The API Key and task mappings live only in the currently open page memory. They are cleared on reload and are never serialized into the workflow, Director JSON, or asset records.

- Uploads use the official `/openapi/v2/media/upload/binary`; asset Path stores the returned `fileName`.
- Queries use `/openapi/v2/query`. One line may be a bare full-workflow `taskId`, `shot_003=taskId` for an explicit shot task, or `merged=taskId` for a historical merge task.
- Full-workflow videos prefer stable Shot IDs found in URLs. If RunningHub returns opaque URLs, videos are assigned cyclically by enabled-shot order; disabled shots consume no position.
- Signed result URLs may expire. Query the task again rather than storing the URL in the plan.
- The cloud UI hides Open results folder. Merge and standalone second pass run through standard partial ComfyUI execution instead of Theodore custom HTTP routes.

## 9. Execution and resume

Use `resume` for normal production. It scans forward from the current Impact index and skips only fully valid results: status, plan hash, shot hash, video, tail, and required latent must all pass.

Current mode behavior:

- `fresh`: forces the current index; it does not reset to shot 1.
- `resume`: skips complete results.
- `retry_failed`: currently identical to `resume`.
- `overwrite_current`: currently identical to `fresh`.

```text
output/TheodoreDirector/<Project name>_<Run ID>/
├─ <shot-id>_video_*.mp4
├─ latent_context/clip_00001.safetensors
├─ tail_frames/<shot-id>_tail_*.png
├─ shot_results/<shot-id>_result.json
└─ manifest.json
```

Video, tail-frame, and result JSON filenames use the stable `shot ID`; disabling, re-enabling, or moving other shots no longer changes that shot's lookup prefix. The Director also recognizes legacy `<execution-index>_<shot-id>_*` files. Disabled shots can still display historical results, but cannot participate in the current execution or video merge. Changing prompts, media, durations, latent relay switches, second-sampling switches, or continuity changes hashes. Old files remain on disk but no longer count as valid completion for the modified plan. Legacy result JSON files in the run-directory root remain readable for resume compatibility, while new results are written to `shot_results/`. Every shot still saves, records, and validates its generated AV latent regardless of whether it consumes the previous latent, so the result remains available for later relay changes or following shots. Change Run ID when you want to retain separate output sets.

## 10. Troubleshooting

- **Save is rejected:** fix each shot named in the alert—commonly alias, path, duration, or capacity errors.
- **Uploaded file is missing:** verify that Project name still matches the value used during upload, check the corresponding input subfolder, and restart after changing relevant environment settings. Files uploaded by older versions under Project ID are not moved automatically; keep their existing path or select and upload them again.
- **`{{ref:...}}` remains in output:** the alias is missing/disabled or generation is not using the H3 Adapter output.
- **Paired audio fails:** confirm video kind, Include video audio, a real audio track, and 2–15-second duration metadata.
- **Base seed changes do nothing:** this is a current implementation limitation. SelectShot's numeric `base_seed` input takes priority, and bundled V6 also connects an external integer.
- **Old output is not skipped:** verify Run ID, output layout, hashes, and result JSON. A tail frame alone is insufficient for current resume validation.
- **Merge button is disabled:** select at least one shot and make sure every selected shot has one generated result selected.
- **FFmpeg is missing:** add FFmpeg to system `PATH`, or set `THEODORE_DIRECTOR_FFMPEG` to the full executable path and restart ComfyUI.
- **FFmpeg reports incompatible parameters:** this release uses lossless stream copy only. Use clips with matching video, audio, and container parameters, or normalize them externally first.
